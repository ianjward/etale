Code where compiling means proving

Most software is built to run first and is tested for trust afterwards. As code moves away from the human domain, that order must flip while remaining comprehensible to all. Trust has to be established before anything runs. Etale uses geometric logic to build systems that can be trusted and explored piece by piece, without the need to write proofs. In Etale, symbolic mathematics becomes ordinary, readable code: compiling it proves each claim for every possible input.

When systems evolve past the human horizon, truths must be visible to all and laid out on common ground, where every claim can be understood, challenged and reasoned about. This is what Etale is for.

  high {Integer} val = -20..40
  spread {Integer} val = high - low
  at_most_60 {Fact} spread <= 60
Why Etale

Guarantees you can rely on, all at once

You write what should hold, and the checker finds the proof.

Proved, not tested

Every file is a specification in geometric logic. A file that compiles is consistent, and each claim in it holds for every possible text, not just recorded test cases.

One meaning

Every reader of a text, person or program, agrees on what it says: every sequence of characters parses exactly one way, or it is refused as ambiguous.

AI reasoning you can see Coming

Proofs have built-in visualizations: a person can step through each one, including the step where a failed proof breaks. An AI can write a claim or a proof, but only the checker can accept it.

No null, no overflow, no division by zero

An empty list is a value, not a missing one. Integers never overflow and decimals are exact. There is no division.

An optional field that is left out reads as 0; count it to tell absent from zero.

No missed cases

A mapping must cover every combination of its inputs, with no two cases overlapping. A missing case is a compile error.

Always finishes In progress

Compiling a file, which proves its claims, and checking a text against it never run forever: a type may contain itself only as a list that can be empty, so every repetition has a place to stop.

No race conditions

Once a text is parsed, its values are fixed. Nothing is ever reassigned, so there is no hidden state and nothing to race over.

No imports, no cycles

A file sees the types of its own folder, the folders above it and the front file of each folder below. Every name has exactly one declaration in scope, and files cannot depend on each other in a circle.

No precedence mistakes

An expression uses one operator kind only, so a + b * c cannot be written, and nothing depends on which operator binds tighter.

Built in Gleam

Rebuild the whole toolchain in your browser

Etale's checker, evaluator and workspace are written in Gleam and compiled to JavaScript. The playground loads the Gleam compiler itself, built to WebAssembly, then compiles Etale's sources and the standard library on your machine and runs the result.

Change a line of the implementation, press Compile, and the workspace beside it is the one you just built. Nothing is sent to a server.

Open the playground
