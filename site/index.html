Sheaf Language Workspace Playground GitHub

Types you can read, checked by geometric logic

Sheaf is a typed language for geometric theories of sequents, written as plain text. A type is the shape of a piece of text; a file of types is a theory; the checker proves facts about every value it could ever see.

Many small typed texts, each checked on its own, glue into one whole, which is where the name comes from.

Types are shapes of text

The grammar is the type

Every type says exactly which texts belong to it. Customer_Code is a C then three digits; a record lists its fields in the order they appear. Data arriving at runtime is read against these types, so a value either fits its type in one way or is reported with the place it went wrong.

The language is described in itself: priv/language.sheaf must match its own File type before anything else runs.

examples/orders/orders.sheafcompiled
# A stock-keeping unit: three capital letters, a dash, four digits.
Sku {Text}
  1. {Uppercase 3}
  2. {"-"}
  3. {Digit 4}

# One order line, e.g. "ABC-0001 x3 @ 19.99".
Line {}
  sku {Sku}
  times {" x"}
  units {Integer} val = 1..1000
  at {" @ "}
  price {Decimal} places = 2 & val >= 0.00
  end {Newline}
  line_total {Decimal} val = units * price & places = 2
Relations are filters

Dot paths reach the record around you

A path that starts with a type name means the nearest enclosing record of that type. Inside an Order, Order.customer is that order's customer code; Book.customers is the customer list of the book holding it.

So “this order belongs to that customer” is a filter, and “there is exactly one” is a count. No foreign keys, no joins: the relation is a type.

examples/book/book.sheafcompiled
Its_Customer {Customer} code = Order.customer

Order {}
  number {Natural}
  gap {" "}
  customer {Customer_Code}
  nl {Newline}
  known {True} Book.customers.Its_Customer.qty = 1

Book {}
  customers {Customer 1..}
  rule {"---"}
  nl {Newline}
  orders {Order 1..}
Proofs

Claims hold for every value

A Fact field is a claim the checker proves for all data, by one fixed method: interval reasoning over the ranges the types allow, and induction over recursive types, assuming the claim for the rest of the chain.

A file whose claims are all proved is outlined purple in the workspace.

examples/proofs/proofs.sheafclaims proved
# A chain of digits written "+3+4+5". Its total is never negative:
# proved by induction, assuming the claim for the rest of the chain.
Chain {}
  plus {"+"}
  x {Integer} val = 0..9
  rest {Chain 0..1}
  total {Integer} val = x + rest.total
  links {Integer} val = rest.qty + rest.links
  nonnegative {Fact} total >= 0
The workspace

Code on a canvas, with its graph

The working file sits in the middle of an infinite canvas; the files it reads fade in beside it when a line names one of their types. Hover a type for its declaration and the base type it reduces to; click to glide there. A second view draws the theory as a graph of types and relations, in rings around the one you pick.

Each file's outline says where it stands:

compiled claims proved changed affected errors locked

Files open read-only with every type a link. Hover to preview, click to bring it to the centre; Alt+← goes back.

Double-click to edit at that spot. With “Check as I type” on, the file and everything that reads it recheck on each keystroke.

03

Probe

Probes are sample texts checked live against a type, so you can see a value parse, or the exact place it stops fitting.

Built in Gleam

Rebuild the whole toolchain in your browser

Sheaf's checker, evaluator and workspace are written in Gleam and compiled to JavaScript. The playground loads the Gleam compiler itself, built to WebAssembly, then compiles Sheaf's sources and the standard library on your machine and runs the result.

Change a line of the implementation, press Compile, and the workspace beside it is the one you just built. Nothing is sent to a server.
